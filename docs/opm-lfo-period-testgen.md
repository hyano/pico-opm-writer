# opm-lfo-period-testgen

[tools/opm-lfo-period-testgen.py](../tools/opm-lfo-period-testgen.py)

[opm-lfo-period.py](opm-lfo-period.md) の回帰テスト。**既知の更新周期を持つ人工信号**を合成して
WAV に書き、解析器に CLI 越しで食わせて、本当にその周期を当てるかを確かめる。
実機もロジックアナライザも要らない。

外部ライブラリは使わない（標準ライブラリのみ）。

## 使い方

```bash
# 全テストを実行する（引数不要）
./tools/opm-lfo-period-testgen.py

# 片方のモードだけ試す
./tools/opm-lfo-period-testgen.py --mode pm

# 生成した WAV を残して中身を見る
./tools/opm-lfo-period-testgen.py --outdir /tmp/lfotest

# 解析器の途中経過も表示する
./tools/opm-lfo-period-testgen.py --verbose
```

出力:

```
PASS am P=8
PASS am P=16
...
PASS am 搬送波不変 (Tc=6.68/10.22/31.78/127.13)
PASS am 非整数周期 P=1000.5
PASS am 近い値の連続 P=4096
PASS am L のみ使用
...
PASS 混在指定 (.wav + .wav.zst)
PASS --mode の必須指定
PASS 壊れた入力の扱い
--- 39 ケース / NG 0
```

**終了コードは失敗が 1 件でもあれば 1**、全部通れば 0。所要は 20 秒程度。

## 引数

| オプション | 既定 | 説明 |
| --- | --- | --- |
| `--mode {am,pm}` | 両方 | このモードだけ試す |
| `--outdir OUTDIR` | 一時ディレクトリ | 生成した WAV を残すディレクトリ |
| `--verbose` | off | 解析器の標準エラー出力も `  \| ` 付きで表示する |

## 作る信号

`test/lfo_noise/opm_seq.txt` が鳴らしているもの（4 オペレータ ALG=7 を同一パラメータで
並列加算した正弦波）を想定し、**単一の正弦波**として合成する。

| モード | 変調のかけ方 | 幅 |
| --- | --- | --- |
| `am` | 振幅を段状に変える | 48dB（AMS=2 相当） |
| `pm` | 搬送波周波数を段状に変える | ±400cent（PMS=7 相当） |

サンプル数は周期の 32 倍を狙い、32768 〜 4194304 の間に収める。R チャネルには実機と同じく
**L の 2 タップ移動平均**を入れる（[opm-dac2wav.md](opm-dac2wav.md#l-と-r-は同一にならない)）。
「L のみ使用」のケースだけ、そこに別の周期・別の搬送波の信号を入れる。

### LFO 値の作り方

W=3 (random) を模した疑似乱数。**わざと近い値・同じ値を連続させる**のが要点で、
2 種類の列を使い分ける。

| 列 | 内容 | 狙い |
| --- | --- | --- |
| 通常 | 一様乱数に、同じ値の連続 / 1 段だけ違う値 / ほぼ同じ値が 3 回続く、を規則的に混ぜる | 通常の掃引に近い条件 |
| 近い値ばかり | 85% は前の値の ±2 以内、15% だけ大きく飛ぶ | イベントの大半がごく小さくなる極端な条件 |

「近い値ばかり」の列では、大きな変化だけを拾う実装は途中の更新を見落として周期を
2 倍・3 倍に取り違える。**この取り違えを検出するのがこのテストの最大の目的。**

## 検査する内容

| ケース | 内容 |
| --- | --- |
| `P=8` 〜 `P=262144` | `8, 16, 32, 64, 128, 256, 512, 1024, 4096, 16384, 65536, 262144` samples を am / pm の両方で |
| 搬送波不変 | 同じ更新周期で搬送波周期だけを `6.68 / 10.22 / 31.78 / 127.13` samples に変え、結果が変わらないこと。解析器が搬送波周波数を必要としていないことの確認 |
| 非整数周期 | `P=1000.5` が小数のまま出ること |
| 近い値の連続 | 上記の極端な列で `P=16 / 256 / 4096` を当てられること |
| L のみ使用 | R チャネルに**別の周期・別の搬送波**の信号を入れても結果が変わらないこと |
| 混在指定 | `.wav` と `.wav.zst` を同時に指定して、同じ結果が出ること。ヘッダが 1 回だけで、標準出力に TSV 以外が混ざらないこと |
| `--mode` の必須指定 | `--mode` 無しで走らせるとエラーで終わり、標準出力に何も出ないこと |
| 壊れた入力の扱い | WAV でないファイルを混ぜても残りの処理が続き、エラーは標準エラーに出て、終了コードだけ 1 になること |

判定は相対誤差 0.5% 以内。あわせて `cycle_count` が `sample_count / period_samples` に
なっていることと、`confidence` が 0〜1 に収まっていることも毎回確かめる。

搬送波の 4 つの値は、実機のキャプチャで使っている搬送波周期の**範囲を代表する点**として選んである。
実機の値と一対一に対応するのは 3 つで、残る 1 つは範囲を埋める中間値:

| Tc [samples] | 由来 |
| --- | --- |
| `127.13` | `KC=0x4a / MUL=1`。`test/lfo_noise/wav_4a_01/` の搬送波（実測 127.0） |
| `31.78` | `KC=0x4a / MUL=4`。`capture_lfo.py` のはしごの先頭（実測 31.78） |
| `10.22` | 特定の KC / MUL に対応しない中間値（はしごの `KC=0x52 / MUL=8` は 11.24） |
| `6.68` | `KC=0x5e / MUL=8`。`test/dac_lr/` の `fast`（実測 6.682） |

**ノイズを加えた信号のテストはしない。** 対象は非常に制御された条件のキャプチャなので、
量子化以外の外乱を模しても得るものが無い。

## 依存

- Python 3（標準ライブラリのみ）
- 同じディレクトリの **`opm-lfo-period.py`** — 無ければ終了コード 1 で終わる
- `.wav.zst` の混在ケースのみ **Python 3.14 以上**が必要。古い Python では `SKIP` 表示で飛ばす
