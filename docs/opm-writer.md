# opm-writer

[tools/opm-writer.py](../tools/opm-writer.py)

シーケンスファイルを USB CDC 経由で pico-opm-writer のファームへ流し込むホスト側ドライバ。
1 行送るごとに応答 (`OK` / `ERR`) を待ち、`!capture` / `!capture-song` の行では
キャプチャを起動する。ファームのコマンド仕様は [README §3](../README.md#3-ホストインタフェース) を参照。

外部ライブラリは使わない（標準ライブラリのみ）。

## 使い方

```bash
# シーケンスを流し込み、!capture の内容を WAV で保存
./tools/opm-writer.py seq.txt out.wav.zst

# プレースホルダを埋める
./tools/opm-writer.py seq.txt out.wav.zst -D LFRQ=a3 -D NFRQ=1f -D TIME=1000

# 実機に触らず、実行内容だけ確認する
./tools/opm-writer.py seq.txt out.wav.zst -D ... -n
```

## 入力ファイルの書式

1 行 1 コマンドのテキストファイル (UTF-8)。ファームへ送る前に次の前処理を行う。

| 書式 | 意味 |
| --- | --- |
| `# ...` | 行頭・行末を問わず、`#` **以降**を捨てる。空になった行は送らない |
| `@KEY@` | `-D KEY=VALUE` で与えた値に置換する。キーに使えるのは `[A-Za-z0-9_]` |
| `!capture <ms>` | ファームへは送らず、`<ms>` ミリ秒のキャプチャを実行する。引数は正の 10 進整数 1 個 |
| `!capture-song <コマンド>` | 演奏 1 曲ぶんをキャプチャする。`<コマンド>`（`vgm play ...` / `mdx play ...`）で曲を始め、**曲が終わるまで**録る。引数は行の残り全部なので、空白を含む曲名も書ける |
| それ以外 | そのままファームへ 1 行送り、応答を待つ |

ファーム側は**行頭 `#` の行しかコメントと見なさない**ため、行末コメントを含むシーケンスは
このスクリプト経由でしか流せない。`@KEY@` と `!capture` / `!capture-song` も同様に
このスクリプトの機能で、ファームは解釈しない。

**`!capture-song` が演奏コマンドを引数に取る**のは、ファーム側の `p 2` が
「次の `play` から録り始める」仕組みだから（[README §3.10](../README.md#310-ppcm-出力)）。
行を分けて書くと `!capture-song` が先にブロックしてしまい、演奏が始まらない。

前処理でエラー（未定義の `@KEY@`、未知の `!` コマンド、`!capture` / `!capture-song` の
引数不正）が 1 つでもあれば、実機には一切触れずに終了コード 1 で終わる。

例（[test/lfo_noise/opm_seq.txt](../test/lfo_noise/opm_seq.txt) から抜粋）:

```
reset                   # ハードウェアリセット
d 100
w 0f @NFRQ@             # NFRQ (00, 1f)
w 18 @LFRQ@             # LFRQ
w 08 78                 # KEY ON
!capture @TIME@
w 08 00                 # KEY OFF
reset
```

曲を 1 本まるごと録る例:

```
mdx loop @LOOP@         # @LOOP@ 周でフェードアウトして終わる
mdx fade 2000
!capture-song mdx play @SONG@
mdx stop
```

## キャプチャの出力形式

**出力ファイル名の拡張子で挙動が決まる。** ファームウェアが YM3012 の出力を取り込んで
CDC #1 から流す signed 16bit LE ステレオ PCM を、ホストがそのまま読む。外部コマンドは使わない。

| 拡張子 | 動作 |
| --- | --- |
| `.wav.zst` | CDC #1 から PCM を読み、WAV を zstd で最大圧縮して書く |
| `.wav` | 同上。圧縮なし |

取り込み中は PCM ポートを止めずに読み続ける必要がある。読まないと 65.5ms 分の
DMA リングが溢れて overrun になる。

動作フロー:

| 種別 | フロー |
| --- | --- |
| `!capture <ms>` | `p 1` を送る → 指定時間ぶん CDC #1 から PCM を読む → `p 0` を送る → ファーム側がリングの残りを送り切るのを待つ → WAV に落とす |
| `!capture-song <コマンド>` | `p 2` を送る（ファームは待機するだけで何も流さない）→ `<コマンド>` を送って演奏を始める → ファームが `# capture : done <n> frames` を出すまで PCM を読む → `p 0` を送る → 同上 |

`!capture-song` の**録り始めは曲の頭、録り終わりは曲の終わり（余韻が消えたところ）**で、
どちらもファームが決める（[README §3.22](../README.md#322-曲の終わり方)）。待っている間の
無音は WAV に入らない。曲が `--song-max-ms`（既定 900000 = 15 分）以内に終わらなければ
失敗として扱い、出力を削除する。ループする曲を録るときは `vgm loop` / `mdx loop` を
先に設定しておくこと。

1 つの入力ファイルに `!capture` / `!capture-song` が複数あるときは、2 個目以降に `-2`, `-3` … を付ける。
`.wav.zst` は 1 つの拡張子として扱うので `out.wav-2.zst` にはならない。

| キャプチャの順番 | 出力 |
| --- | --- |
| 1 個目 | `out.wav.zst` |
| 2 個目 | `out-2.wav.zst` |

キャプチャに失敗した場合、書きかけの出力ファイルは削除する（短い WAV がデータセットに
混ざる方が厄介なため）。**要求した長さのキャプチャが届かなかった回も失敗として扱う**
（下の「キャプチャ長の検査」）。

## 引数

### 位置引数

| 引数 | 説明 |
| --- | --- |
| `input` | 入力シーケンスファイル |
| `capture` | キャプチャの出力ファイル名。拡張子で形式が決まる（上表） |

### オプション

| オプション | 既定 | 説明 |
| --- | --- | --- |
| `-D`, `--define KEY=VALUE` | なし | `@KEY@` の置換値。複数指定可 |
| `--device DEVICE` | 自動検出 | コマンド用 USB CDC のデバイス |
| `--pcm-device DEVICE` | 自動検出 | PCM 出力の USB CDC のデバイス |
| `--phim PHIM` | `4000000` | OPM の φM [Hz] |
| `--zstd-level N` | `22` | `.wav.zst` の圧縮レベル（22 = 最大） |
| `--song-max-ms MS` | `900000` | `!capture-song` が 1 曲に費やす上限 [ms]。超えたら失敗 |
| `-n`, `--dry-run` | off | シリアルに触らず、実行内容だけ表示する |
| `--stop-on-error` | off | エラーが出た時点で中断する。既定は警告して続行 |

既定では USB インタフェース名 `pico-opm-writer command` / `pico-opm-writer PCM` で IORegistry を引いて
自動で見つかるため、通常は指定不要。このため PicoProbe 側の CDC-UART ブリッジを誤って掴むこともない。
`--device` / `--pcm-device` を明示すると自動検出を上書きでき、同じインタフェース名の機器が複数繋がっている
ときは明示指定すること。

## 出力

標準出力（行頭 1 文字で種別が分かる）:

| 接頭辞 | 意味 |
| --- | --- |
| `> ` | ファームへ送った行 |
| `< ` | ファームからの応答（`#` の情報行を含む） |
| `$ ` | これから行うキャプチャの内容（`p 1` / `p 2` → PCM ポート → 出力先 → `p 0`） |
| `* ` | 生成した出力ファイルとバイト数、および実際に届いたキャプチャの秒数 |
| `--- ` | 末尾のサマリ（送信行数 / キャプチャ件数 / エラー件数） |

エラーは `! ` を付けて標準エラーへ出す。終了コードはエラー 0 件で 0、それ以外は 1。

## 依存

- Python 3（標準ライブラリのみ）
- POSIX の `termios` — シリアルを直接開くため。Windows では動かない

`.wav.zst` 出力には Python 3.14 以上が必要（`compression.zstd` module）。古い Python では
`.zst` を指定した時点でエラーになる。代わりに `.wav` で出力するか、外部コマンドで圧縮する。

## 補足

### 応答待ちのタイムアウト

コマンドによって待ち時間を変えている。ファーム側の実行時間に依存するため、
コマンドを追加したときはここも合わせる必要がある。

| コマンド | 待ち時間 | 補足 |
| --- | --- | --- |
| `d <ms>` | 5 秒 + `<ms>` |  |
| `reset` / `c` | 10 秒 |  |
| `p` | 10 秒 | サブコマンドによらず `REPLY_TIMEOUT_S` 5 秒 + `PCM_DRAIN_TIMEOUT_S` 5 秒。`p 0` がリング残りを送り切るのを待つぶん（ファーム側上限 2 秒） |
| その他 | 5 秒 |  |

キャプチャ側は、要求した `<ms>` ぶん読んだあと `p 0` の応答を最大 5 秒
(`PCM_DRAIN_TIMEOUT_S`) 待ち、応答後もさらに 0.3 秒ぶん無音が続くまで残りを拾う
（ファーム側がリングを送り切る上限は 2 秒）。

### キャプチャ長の検査

`!capture <ms>` で届くべきバイト数は `φM / 64 × 4 × ms / 1000` で決まる（PCM は
1 フレーム 4 バイト、レートは φM/64）。実際に届いた量がその **99%** (`CAPTURE_SHORT_RATIO`)
を下回ったら失敗として扱い、出力を削除して終了コード 1 を返す。

```
! seq.txt:12: !capture 120000: キャプチャが短い: 0.854s / 要求 120.000s (0.7%)
```

ホストが PCM ポートの読み取りに失敗してもファーム側は実行を続けるため、この検査が
無いと短いキャプチャが成功として保存される。

**`!capture-song` では長さを検査しない。** 曲の長さは事前に分からず、比べる要求値が
存在しない。代わりに「1 バイトも届かなかった」場合と「`--song-max-ms` に達した」場合を
失敗として扱い、同じように出力を削除する。

```
! seq.txt:3: !capture-song mdx play LOOP.MDX: 曲が 900000 ms 以内に終わらなかった（--song-max-ms で伸ばすか、vgm loop / mdx loop を設定すること）
```

### 起動時の挙動

SWD の `reset` 直後はデバイスノードが数秒消えるため、最大 10 秒まで出現を待つ。
接続後は 1 秒ぶんの出力を読み捨ててから送信を始める（ファームは接続検出時に
起動バナーを出すため）。

デバイスが `EBUSY` で開けない場合は、`screen` や `minicom` が掴んだままになっていないか確認する。
