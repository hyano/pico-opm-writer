# opm-writer

[tools/opm-writer.py](../tools/opm-writer.py)

シーケンスファイルを USB CDC 経由で pico-opm-writer のファームへ流し込むホスト側ドライバ。
1 行送るごとに応答 (`OK` / `ERR`) を待ち、`!capture` の行ではロジックアナライザ (sigrok-cli) の
キャプチャを起動する。ファームのコマンド仕様は [README §4](../README.md#4-ホストインタフェース) を参照。

外部ライブラリは使わない（標準ライブラリのみ）。

## 使い方

```bash
# シーケンスを流し込み、!capture の内容を生キャプチャで保存
./tools/opm-writer.py seq.txt out.bin

# 同上。sigrok-cli の出力をパイプでデコードして WAV へ（.bin は残さない）
./tools/opm-writer.py seq.txt out.wav.zst

# プレースホルダを埋める
./tools/opm-writer.py seq.txt out.wav.zst -D LFRQ=a3 -D NFRQ=1f -D TIME=1000

# 実機にもロジアナにも触らず、実行内容だけ確認する
./tools/opm-writer.py seq.txt out.wav.zst -D ... -n
```

## 入力ファイルの書式

1 行 1 コマンドのテキストファイル (UTF-8)。ファームへ送る前に次の前処理を行う。

| 書式 | 意味 |
| --- | --- |
| `# ...` | 行頭・行末を問わず、`#` **以降**を捨てる。空になった行は送らない |
| `@KEY@` | `-D KEY=VALUE` で与えた値に置換する。キーに使えるのは `[A-Za-z0-9_]` |
| `!capture <ms>` | ファームへは送らず、`<ms>` ミリ秒のキャプチャを実行する。引数は正の 10 進整数 1 個 |
| それ以外 | そのままファームへ 1 行送り、応答を待つ |

ファーム側は**行頭 `#` の行しかコメントと見なさない**ため、行末コメントを含むシーケンスは
このスクリプト経由でしか流せない。`@KEY@` と `!capture` も同様にこのスクリプトの機能で、
ファームは解釈しない。

前処理でエラー（未定義の `@KEY@`、未知の `!` コマンド、`!capture` の引数不正）が 1 つでも
あれば、実機には一切触れずに終了コード 1 で終わる。

例（[test/lfo_noise/opm_seq.txt](../test/lfo_noise/opm_seq.txt) から抜粋）:

```
r                       # ハードウェアリセット
d 100
w 0f @NFRQ@             # NFRQ (00, 1f)
w 18 @LFRQ@             # LFRQ
w 08 78                 # KEY ON
!capture @TIME@
w 08 00                 # KEY OFF
r
```

## キャプチャの出力形式

**出力ファイル名の拡張子で挙動が決まる。**

| 拡張子 | 動作 | ディスクに落ちるもの |
| --- | --- | --- |
| `.wav.zst` | sigrok-cli の出力をデコーダへ中継し、WAV を zstd 圧縮して書く | `.wav.zst` のみ |
| `.wav` | 同上。圧縮なし | `.wav` のみ |
| それ以外（`.bin` 等） | sigrok-cli の生キャプチャをそのまま保存する | 生キャプチャ（8MB/s） |

`.wav` / `.wav.zst` では生キャプチャも中間の WAV もディスクに落とさない。10 秒のキャプチャが
80MB の `.bin` + 2.5MB の `.wav` ではなく、数百 KB の `.wav.zst` だけになる。
代わりにデコードがその場で走るので、`--phim` などを間違えるとその条件は取り直しになる。
信号の質を直接見たいときは `.bin` で撮る。

### 中継はこのスクリプトが行う

**sigrok-cli とデコーダを直結してはいけない。** デコーダが 1 チャンクを処理している間
パイプは読まれず、OS のパイプ容量（64KiB = 8MB/s で 8ms ぶん）を超えると sigrok-cli の
`write` が待たされる。その間 sigrok-cli は libusb の転送を回せないのでロジアナ側の FIFO が
溢れ、取得が途中で死ぬ。しかも sigrok-cli はそれでも**終了コード 0 で終わる**ため、
短いキャプチャが黙って通る。

そこで、キャプチャ中はほかに何もしていない親プロセスがデータの中継役に回る。

```
sigrok-cli --stdout ──> opm-writer.py（RAM のバックログ）──> opm-dac2wav.py ──> out.wav.zst
                        └ 常に読み出す                       └ 遅れてもよい
```

デコーダが一時的に遅れてもそのぶんは RAM に積まれるだけで、sigrok-cli は待たされない。
バックログが `PUMP_BACKLOG_MAX`（256MB）を超えたらそこで失敗にする。データを黙って
壊すより落とす方がよいため。

1 つの入力ファイルに `!capture` が複数あるときは、2 個目以降に `-2`, `-3` … を付ける。
`.wav.zst` は 1 つの拡張子として扱うので `out.wav-2.zst` にはならない。

| `!capture` の順番 | `out.bin` の場合 | `out.wav.zst` の場合 |
| --- | --- | --- |
| 1 個目 | `out.bin` | `out.wav.zst` |
| 2 個目 | `out-2.bin` | `out-2.wav.zst` |

キャプチャに失敗した場合、書きかけの出力ファイルは削除する（短い WAV がデータセットに
混ざる方が厄介なため）。**要求した長さのキャプチャが届かなかった回も失敗として扱う**
（下の「キャプチャ長の検査」）。

## 引数

### 位置引数

| 引数 | 説明 |
| --- | --- |
| `input` | 入力シーケンスファイル |
| `capture` | キャプチャの出力ファイル名。拡張子で形式が決まる（上表） |

### オプション

| オプション | 既定 | 説明 |
| --- | --- | --- |
| `-D`, `--define KEY=VALUE` | なし | `@KEY@` の置換値。複数指定可 |
| `--device DEVICE` | `/dev/cu.usbmodem112101` | USB CDC のデバイス |
| `--samplerate SAMPLERATE` | `8m` | sigrok-cli の samplerate。`8m` / `16MHz` / `8000000` の表記を解釈してデコーダの `--la-rate` にも渡す |
| `--phim PHIM` | `4000000` | OPM の φM [Hz]。`.wav` / `.wav.zst` のときデコーダへ渡す |
| `--zstd-level N` | `22` | `.wav.zst` の圧縮レベル（22 = 最大） |
| `-n`, `--dry-run` | off | シリアルも sigrok も触らず、送信する行と組み立てたコマンドラインだけ表示する |
| `--stop-on-error` | off | エラーが出た時点で中断する。既定は警告して続行 |

`--device` は **ターゲット pico2 自身の USB CDC**（`printf` の出力先）を指す。PicoProbe 側の
CDC-UART ブリッジではない。tty 名の引き直し方は [README §6](../README.md#6-ビルドと書き込み) を参照。

## 出力

標準出力（行頭 1 文字で種別が分かる）:

| 接頭辞 | 意味 |
| --- | --- |
| `> ` | ファームへ送った行 |
| `< ` | ファームからの応答（`#` の情報行を含む） |
| `$ ` | 実行した外部コマンドライン |
| `\| ` | 子プロセス (sigrok-cli / opm-dac2wav.py) の標準エラー |
| `* ` | 生成した出力ファイルとバイト数、および実際に届いたキャプチャの秒数 |
| `--- ` | 末尾のサマリ（送信行数 / キャプチャ件数 / エラー件数） |

エラーは `! ` を付けて標準エラーへ出す。終了コードはエラー 0 件で 0、それ以外は 1。

## 依存

- Python 3（標準ライブラリのみ）
- **`sigrok-cli`** — `!capture` を使う場合。ドライバは `fx2lafw` 固定
- **[opm-dac2wav.py](opm-dac2wav.md)** — `.wav` / `.wav.zst` 出力の場合。同じディレクトリにある前提で、
  無ければ実行前に終了する
- POSIX の `termios` — シリアルを直接開くため。Windows では動かない

`.wav.zst` 出力はデコーダ側が zstd を扱えることが前提（Python 3.14 以上）。詳細は
[opm-dac2wav.md](opm-dac2wav.md#依存) を参照。

## 補足

### 応答待ちのタイムアウト

コマンドによって待ち時間を変えている。ファーム側の実行時間に依存するため、
コマンドを追加したときはここも合わせる必要がある。

| コマンド | 待ち時間 |
| --- | --- |
| `d <ms>` | 5 秒 + `<ms>` |
| `r` / `c` | 10 秒 |
| その他 | 5 秒 |

キャプチャ側のタイムアウトは、生キャプチャならキャプチャ時間 + 30 秒、パイプ経路なら
キャプチャ時間 + 120 秒（デコードと zstd の最終フラッシュが後ろに残るため）。

### キャプチャ長の検査

`-O binary` は 1 サンプル 1 バイトなので、`!capture <ms>` で届くべきバイト数は
`samplerate × ms / 1000` で決まる。実際に届いた量がその **99%** (`CAPTURE_SHORT_RATIO`)
を下回ったら失敗として扱い、出力を削除して終了コード 1 を返す。生キャプチャ経路
（ファイルサイズで判定）とパイプ経路（中継したバイト数で判定）の両方に掛かる。

```
! seq.txt:12: !capture 120000: キャプチャが短い: 0.854s / 要求 120.000s (0.7%)
```

ロジアナ側の取得が途中で死んでも sigrok-cli は終了コード 0 で終わるため、この検査が
無いと短いキャプチャが成功として保存される。`--samplerate` の表記が解釈できない場合
（`parse_samplerate` が読めない値）は検査を飛ばす。

ロジアナが要求した samplerate を出せず別の値に丸めた場合もこの検査に引っ掛かるが、
それは正しい挙動である。同じ値がデコーダの `--la-rate` にも渡っているので、通してしまうと
時間軸のずれた WAV が黙って出来上がる。

### 起動時の挙動

SWD の `reset` 直後はデバイスノードが数秒消えるため、最大 10 秒まで出現を待つ。
接続後は 1 秒ぶんの出力を読み捨ててから送信を始める（ファームは接続検出時に
起動バナーを出すため）。

デバイスが `EBUSY` で開けない場合は、`screen` や `minicom` が掴んだままになっていないか確認する。
