# opm-lfo-period

[tools/opm-lfo-period.py](../tools/opm-lfo-period.py)

YM2151 の実機キャプチャから **LFO の更新周期をサンプル数で測る**。
[test/lfo_noise/](../test/lfo_noise/README.md) が集めた `.wav.zst` を読み、1 ファイル 1 行の TSV を出す。
`LFRQ` 設定値と実測の更新周期の対応表を作るためのツール。

LFO 波形は **W=3 (random)** を想定している。この波形では LFO の値そのものに周期性は無く、
周期があるのは**更新のタイミングだけ**。したがってこのツールが測るのは
「LFO のランダム値の周期」ではなく「更新イベントの間隔」である。

外部ライブラリは使わない（標準ライブラリのみ）。`.wav.zst` はメモリ上で展開するので、
中間の WAV ファイルは作らない。

## 使い方

```bash
# PM キャプチャを 1 本解析する
./tools/opm-lfo-period.py --mode pm test/lfo_noise/wav/pm_nfrq_00_lfrq_a3_kc_4a_mul_04.wav.zst

# AM キャプチャをまとめて解析して TSV に落とす（.wav と .wav.zst は混ぜてよい）
./tools/opm-lfo-period.py --mode am test/lfo_noise/wav/am_*.wav.zst > result.tsv

# 途中経過を見る（標準出力は TSV のまま）
./tools/opm-lfo-period.py --mode pm -v foo.wav.zst
```

出力:

```
file	mode	channel	sample_count	period_samples	cycle_count	confidence
wav/am_nfrq_00_lfrq_20_kc_4a_mul_04.wav.zst	am	L	2096807	65536.5753	31.9945	0.7513
```

**標準出力は TSV だけ**、エラー・警告・途中経過はすべて標準エラーへ出す。
`> result.tsv` の結果をそのまま別のプログラムに食わせられる。
読めないファイルがあっても残りの処理は続き、**終了コードだけが 1** になる。

### 解析モードは必ず指定する

`--mode am` / `--mode pm` は必須。**入力ファイル名や内容から AM/PM を判定することはしない。**
`test/lfo_noise/wav/` の `am_` / `pm_` という命名はどのサンプルを使うかという運用上の約束で
あって、このツールの仕様ではない。

## 出力する項目

| 列 | 内容 |
| --- | --- |
| `file` | 入力ファイル名（指定されたそのまま） |
| `mode` | `am` または `pm`（`--mode` の指定そのまま） |
| `channel` | 常に `L` |
| `sample_count` | 解析対象にした L チャネルの総サンプル数 |
| `period_samples` | 推定した LFO 更新周期 [samples]。整数に極めて近くても小数のまま出す |
| `cycle_count` | `sample_count / period_samples` |
| `confidence` | 推定周期の信頼度 0〜1 |

## 引数

### 位置引数

| 引数 | 説明 |
| --- | --- |
| `input` | 入力する WAV。複数指定可。`.wav` と `.wav.zst` を混ぜてよい |

### オプション

| オプション | 既定 | 説明 |
| --- | --- | --- |
| `--mode {am,pm}` | なし（必須） | 解析モード。`am`=振幅変調 / `pm`=位相変調 |
| `--no-header` | off | TSV のヘッダ行を出さない。複数回の実行を連結するときに使う |
| `-v`, `--info` | off | 候補・歩き上がり・内訳を標準エラーに出す |

## 入力の前提

| 項目 | 前提 |
| --- | --- |
| WAV | 16bit ステレオ。**L チャネルだけを使う**（R は読まない） |
| 音源 | 1 チャネル / 4 オペレータ / **ALG=7**（4 並列加算）/ 4 オペレータ同一パラメータ |
| 波形 | 正弦波 |
| LFO | **W=3 (random)** |
| キャプチャ中 | レジスタ更新なし。波形の変化は LFO によるものだけ |

R を使わないのは、DAC CH2 が CH1 の半フレーム後にラッチされるため
**L と R が同一にならない**から（[test/dac_lr/](../test/dac_lr/README.md)）。

**搬送波の情報（KC / MUL / 音程）は一切入力しない。** 搬送波周期は波形から測る。
サンプリングレートも同じで、**WAV ヘッダのレートは解析に使わない**。時間はすべてサンプル数で扱う。

## アルゴリズム

### 更新イベントを階段状の量の差分として取り出す

ALG=7 で 4 オペレータのパラメータが揃っているので、出力は**単一の正弦波**になる。
更新イベントの間では振幅も周波数も一定なので、信号は線形漸化式

    x[n+1] = 2 cos(ω) x[n] - x[n-1]

を厳密に満たす。ここから搬送波周波数を仮定せずに次の 2 つを取り出せる。

| モード | 取り出す量 | 求め方 |
| --- | --- | --- |
| `am` | 包絡線 | `env[n]² = x[n]² + ((x[n+1] - x[n-1]) / (2 sin ω))²` |
| `pm` | 局所的な `cos(ω)` | 最小二乗 `Σ x[n](x[n-1]+x[n+1]) / (2 Σ x[n]²)` |

包絡線の式は**一定振幅の正弦波に対して厳密**（近似ではない）。`ω` はファイル全体に散らした
チャンクから最小二乗で 1 度だけ求める（波形から測るので搬送波を外から与えたことにはならない）。

どちらの量も更新イベントの所でだけ段差になる**階段状の量**なので、その 1 階差分が
イベント列（インパルス列）になる。以降はこの列の周期だけを見る。

PM の `cos(ω)` は零交差の近くで分母が消えて値が暴れる。そこは推定が効いていないだけなので、
ブロックのエネルギー（= 推定の効き具合）を重みに掛けて潰す。これで搬送波位相に由来する
偽のイベントが消える。

### 8 〜 262144 samples を 1 つの仕組みで扱う

`x[n]` の累積和を**1 パスだけ**作り、以降のすべてのスケールをそこから O(1)/ブロックで出す。
ブロック長 `s` を変えると同じ式が別のスケールの解析器になる。

- 短周期 → `s = 1`（サンプル単位の分解能）
- 長周期 → `s ≒ P / 32`（平均化で背景ノイズが落ち、疎なイベントが浮き上がる）

**`s` を固定すると片方が必ず壊れる。** 長周期側を `s = 1` で見ると、262144 サンプルに 1 個しか
無いイベントが全区間の背景ノイズに埋もれて完全に検出できない。逆に短周期側を粗いブロックで
見るとイベントが均されて消える。

スケール `s` は周期 `[8s, 64s]` を担当し、`s` を 4 倍ずつ上げて全域を覆う。

### 周期は「折り返しの集中度」で測る

候補周期 `Q` でイベント列を折り返し、1 次高調波の集中度を見る。

    score(Q) = |Σ d[j] · exp(-2πi·j/Q)| / Σ d[j]

イベントが `Q` 間隔で並んでいれば 1 に近づく。**イベントの値ではなく位置しか見ていない**ので、
W=3 のランダムな LFO 値でも成立する。粗探索は短い区間で対数間隔に振り（サイクル数が
少ないほどピークが太くなり粗い刻みで捕まる）、候補が決まってからデータ量を増やして絞り込む。

### 半周期・倍周期を取り違えない

イベントが間隔 `P` で並んでいるとき、

| 折り返す周期 | 集中度 | 理由 |
| --- | --- | --- |
| `P` の約数（`P/2`, `P/3` …） | **高いまま** | `P` の倍数は約数の倍数でもあるので、全イベントが同じビンに落ちる |
| `P` | 高い | |
| `P` の倍数（`2P`, `3P` …） | **崩れる** | イベントが等間隔の複数ビンに割れ、1 次高調波が打ち消し合う |

したがって**「集中度が高いまま到達できる最大の周期」が真の周期**になる。候補から 2 倍・3 倍へ
歩き上がり、集中度が崩れた所で止める。

比較は必ず**今の候補に合わせた細かい方のブロック長**の上で行う。倍側の粗いブロックで比べると
小さい周期だけがぼけて不利になり、上がりすぎる。

また、候補の周りを細かく走査する窓は**候補周期の ±25% に制限する**。サイクル数の少ない
条件では窓が広がりすぎ、「2 倍」を探しているのに窓の中に元の周期が入って、それを拾って
しまう。倍・3 倍の候補と混ざらない幅に抑えることで、歩き上がりの判定が意味を持つ。

実測での分離（`score(kQ) / score(Q)`）:

| 状況 | 比 |
| --- | --- |
| 約数にいて真の周期へ上がるべき | 0.95 〜 3.5（多くは 1.0 以上） |
| 既に真の周期にいる（実機データ） | 0.30 以下 |
| 既に真の周期にいる（イベントが極端に少ない合成波形） | 0.79 |

閾値はこの間を取って **0.88**（相対）。あわせて**集中度そのものが 0.30 以上**であることも
要求する。両方を満たしたときだけ上へ進む。

### 連続して近いランダム値が出た場合

W=3 では隣り合う更新値がたまたま近くなることがあり、そのときイベントはほとんど見えない。
このツールは **`abs(値[n] - 値[n-1]) > 閾値` のような単純な変化量の閾値検出を使っていない。**
全イベントを折り返して統計的にタイミングを見るので、一部のイベントが弱くても周期は残る。

弱いイベントが混ざっても倍周期に化けないのは、**欠落がランダムに散らばる**から。`P/2` を疑う
ときのように**規則的に半分が空になる**のとは折り返しの崩れ方が違う。

### 小数の周期を詰める

記録を `k` 区間に分け、各区間で折り返し位相を測る。真の周期が候補からずれていると位相が
区間ごとに一定の割合で流れるので、その傾き `β` から

    1/P = 1/Q + β/2π

で周期が出る。`k` を 2 → 4 → 8 …と増やしながら候補を良くしていくので、次の分割での
位相のアンラップが安全になる。この詰めはイベント検出より**細かいブロック長**で行う
（粗いブロックは位相を偏らせ、65536 に対して十数サンプルの偏りが出る）。

### confidence の求め方

次の 4 つの積。すべて 0〜1。

| 要素 | 内容 |
| --- | --- |
| `align` | 最終的な周期での折り返し集中度。更新イベントがその周期に整列している度合い |
| `consist` | 区間ごとの折り返し位相を直線あてはめしたときの**残差の位相ベクトル和**。複数区間で同じ周期が得られているか。4 分割以上できたときだけ採用し、届かなければ `enough` で代用する（2 点や 3 点では直線が必ず通ってしまうため） |
| `margin` | `1 - max(score(2P), score(3P)) / score(P)`。倍周期候補との差 |
| `enough` | `min(1, cycle_count / 8)`。1 周期分しか観測できていないデータを信用しないため |

**「P サンプル前の値と似ている」ことは根拠にしていない。** W=3 では LFO 値そのものはランダムなので、
値の再現性ではなく**更新タイミングの周期性**だけを評価している。

目安として、実機データでは 0.5 〜 0.99 に収まる。周期が短いほど、イベントの位置の揺らぎが
周期に対して相対的に大きくなるので `align` が下がり、confidence も下がる。

### 搬送波との共振の警告

推定周期が搬送波周期の `k/2` 倍（`k ≤ 16`）に近い、すなわち搬送波周期に対する比と
`k/2` との**差が 0.04 以内**（`RESONANCE_TOL`）だと、搬送波由来の成分と
区別が付かない。その場合は標準エラーに警告を出す（TSV には出さない）。
**別の KC / MUL でキャプチャし直して同じ値になるか確かめること。**

判定に使う搬送波周期は `-v` が表示するものと同じ**全区間の平均値**なので、変調が深い条件では
真の搬送波周期から偏る（実測の例は
[test/lfo_noise/README.md](../test/lfo_noise/README.md#53-測定の限界) §5.3）。周期の推定そのものは
この値を使っていないので影響を受けないが、警告が出る/出ないの境目はこの偏りぶんずれる。

## `.wav.zst` の読み込み

先頭 4 バイトが zstd のマジック (`28 b5 2f fd`) なら、`compression.zstd.decompress()` で
**メモリ上に**展開してそのまま `wave` に食わせる。ディスク上に中間の WAV は作らない。

```
.wav.zst → compression.zstd.decompress → io.BytesIO → wave → array('h') → L チャネル
```

L チャネルの取り出しは `array('h')` のストライドスライス (`samples[0::nch]`) で、
Python のループを通さない。

## 依存

- Python 3（標準ライブラリのみ）
- `.wav.zst` を読む場合のみ **Python 3.14 以上**（`compression.zstd`, PEP 784）。
  古い Python では `.wav` に展開してから渡す

## 性能

支配的なのは累積和を作る O(N) の 1 パスだけで、探索は縮約済みの小さい配列の上で行う。

| サンプル数 | 所要 |
| --- | --- |
| 31,244（0.5 秒キャプチャ） | 0.3 秒 |
| 2,096,807 | 0.7 秒 |
| 7,498,868（120 秒キャプチャ） | 1.6 秒 |

`test/lfo_noise/wav/` の 1 グループ（256 条件）で 1 分 43 秒、1024 条件全部でも 7 分程度。
