# opm-dac2wav

[tools/opm-dac2wav.py](../tools/opm-dac2wav.py)

sigrok-cli でキャプチャした YM2151 (OPM) の DAC 出力信号を、16bit ステレオの WAV に変換する。
OPM は音声をアナログではなく **YM3012 (DAC-MS) 向けのシリアルビット列**として出す。
その SO / SH1 / SH2 の 3 線を φ1 と一緒にロジックアナライザで撮り、デジタルのまま
デコードする。

外部ライブラリは使わない（標準ライブラリのみ）。

## 使い方

```bash
# 撮る（1 サンプル 1 バイトの生ロジックデータ）
sigrok-cli -d fx2lafw --config samplerate=8MHz -O binary --time=50s -o cap.bin

# 変換する
./tools/opm-dac2wav.py cap.bin out.wav -v

# パイプで繋いで .bin を残さない（opm-writer.py の .wav.zst 出力はこれを組む）
sigrok-cli -d fx2lafw --config samplerate=8MHz -O binary --time=50s \
  | ./tools/opm-dac2wav.py - out.wav.zst -v
```

## 入力

`sigrok-cli -O binary` の出力。**1 サンプル 1 バイト**で、下位ビットに各チャネルが入る。
既定の配線は次のとおり。

| ロジアナ CH | ビット | OPM 端子 | 役割 |
| --- | --- | --- | --- |
| CH0 | bit0 | φ1 | ビットクロック（φM/2） |
| CH1 | bit1 | SO | シリアルデータ |
| CH2 | bit2 | SH1 | CH2 のサンプルホールド |
| CH3 | bit3 | SH2 | CH1 のサンプルホールド |

別の配線で撮ったときは `--map` で割り当てを変える（例: `--map phi1=3,so=0,sh1=1,sh2=2`）。

サンプルレートは 8MHz を既定とする。φ1 は φM/2 = 2MHz なので 1 周期あたり 4 サンプルしかない。
再同期が多発する場合は 16MHz で撮り、`--la-rate 16000000` を渡す。

## 出力

16bit ステレオ、リトルエンディアンの非圧縮 WAV。**サンプルレートは φM/64**
（φM = 4MHz で 62500Hz、NTSC の 3.579545MHz で 55930Hz）。

L/R の割り当ては既定で **CH1 = L / CH2 = R**。逆に出る配線なら `--swap` を付ける。
これは実測で決めたもので、レジスタ `$20` の RL を片側だけ立てて撮ると、bit6 (L) だけなら
CH2 が全サンプル厳密に 0、bit7 (R) だけなら CH1 が全サンプル厳密に 0 になる
（根拠: [test/dac_lr/](../test/dac_lr/README.md#51-デコードは正しい) の `fast_4op_left` / `fast_4op_right`）。

出力名が `.zst` で終わる場合は zstd で圧縮して書く。`-` を指定すると標準出力へ出す
（このとき統計・警告はすべて標準エラーへ出るので、標準出力は WAV データ専用になる）。

デコードに失敗したとき、および**フレームを 1 つもデコードできなかったとき**は、書きかけの
出力ファイルを削除して終了コード 1 を返す。空の `.wav.zst` が残ると呼び出し側が完了と誤認するため。

### L と R は同一にならない

**1 チャネルを `RL=both` で鳴らしても、L と R はサンプル単位では一致しない。**
これはデコードの誤りではなく OPM の出力そのもの。以下は実測とその説明で、根拠は
[test/dac_lr/](../test/dac_lr/README.md) にある（16 条件ぶんの一次データ付き）。

実測（16 条件すべてで再現）:

- 単独オペレータでは、`+0x00` / `+0x08` を鳴らすと `R[i] = L[i]` が**整数値で厳密に**成り立ち、
  `+0x10` / `+0x18` を鳴らすと `R[i] = L[i+1]` が厳密に成り立つ
- 両群から 1 個ずつ鳴らすと `R[i] = (L[i] + L[i+1]) / 2` になる（残差 −61dB）

これを説明できる機序（YM3012 のフレーム構造からの推論であって、OPM 内部を直接観測した
ものではない）: 1 サンプル = φ1 32 クロックで、DAC は 16 クロックごとに CH1 → CH2 と送出する。
CH2 のラッチは CH1 の半フレーム後にあり、その間に更新されたオペレータの寄与は次のサンプルの
値に入れ替わっている。

いずれにせよ、両群が均等に鳴っているとき（4 オペレータを同条件で鳴らす場合など）、R は
**L の 2 タップ移動平均** `R[i] = (L[i] + L[i+1]) / 2` になる。周波数特性は
`cos(π f / fs)` のローパスで、R は独立なサンプルではない。

したがって**波形解析には片側（既定なら L = CH1）だけを使う**。

### 長い出力ではヘッダのサイズ欄が不定になる

WAV ヘッダのサイズ欄は全データを書き終えるまで確定しない。パイプや zstd ストリームへ
書けるようにするため、PCM は **64MiB**（62500Hz / 16bit / stereo で約 17 分）までメモリに
溜めてから、サイズ欄を埋めたヘッダごと一気に書き出す。

これを超えた場合の挙動は出力先で変わる。

| 出力先 | 挙動 |
| --- | --- |
| ファイル（シーク可能） | サイズ欄 `0xFFFFFFFF` のヘッダを先に書いて素通しに切り替え、最後にサイズ欄を実測値で上書きする |
| 標準出力・zstd ストリーム（シーク不可） | サイズ欄が `0xFFFFFFFF` のままの**長さ不定の WAV** になる。標準エラーに警告を出す |

長さ不定の WAV は `wave` などのライブラリでは読めるが、**ヘッダだけを見る検査は効かなくなる**
（[capture_lfo.py](../test/lfo_noise/README.md#33-撮れているかの検査) の `--check` はこれを
「検査できず」として飛ばす）。既定の掃引はキャプチャ上限 120 秒＝約 30MB なので、この経路には入らない。

## 引数

### 位置引数

| 引数 | 説明 |
| --- | --- |
| `input` | キャプチャファイル (`-O binary`)。`-` で標準入力 |
| `output` | 出力する WAV ファイル。`-` で標準出力、`.zst` で終わる名前なら zstd で圧縮する |

### オプション

| オプション | 既定 | 説明 |
| --- | --- | --- |
| `--phim PHIM` | `4000000` | OPM の φM [Hz]。出力レート (φM/64) と φ1 の期待値を決める。NTSC は `3579545` |
| `--la-rate LA_RATE` | `8000000` | ロジアナのサンプルレート [Hz]。統計の秒数換算と φ1 実測値に使う |
| `--map SPEC` | `phi1=0,so=1,sh1=2,sh2=3` | ビット割り当て。`NAME=BIT` をカンマ区切り。名前は `phi1` / `so` / `sh1` / `sh2`、ビットは 0-7 で重複不可 |
| `--swap` | off | CH1 を R、CH2 を L にする |
| `--max-seconds SEC` | 全部 | 先頭から指定秒数ぶんだけ変換する |
| `--delta N` | 自動 | ビット位相を自動判定せず `-2`..`2` に固定する |
| `--zstd-level N` | `22` | 出力が `.zst` のときの圧縮レベル（22 = 最大） |
| `-v`, `--info` | off | 統計を標準エラーへ表示する |

## 依存

- Python 3（標準ライブラリのみ）
- **`.zst` の入出力には Python 3.14 以上が必要** — `compression.zstd` (PEP 784) を使う。
  古い Python では `.zst` を指定した時点でエラーになる（ファイルを作る前に弾くので、
  空ファイルは残らない）。代わりに外部コマンドへ繋ぐ:
  ```bash
  ./tools/opm-dac2wav.py cap.bin - | zstd -22 --ultra -o out.wav.zst
  ```

外部コマンドは呼ばない（[opm-writer.py](opm-writer.md) から呼ばれる側）。

## 統計 (`-v`) の読み方

```
* out.wav : 5996 フレーム / 62500Hz / 16bit stereo (0.096s)
* 入力 767807 サンプル (0.096s @ 8MHz)
* φ1 191946 クロック = 1.9999MHz (期待値 2MHz)
* フレーム 5996 個 = 0.096s @ 62500Hz
* 捨てた冒頭 2 サンプル / ビット位相 delta=0
* 位相候補 (禁止コード数/差分和) +0:0/210495060 -1:493/153129904 +1:2389/90739232 -2:950/144228752 +2:1263/75376630
* 再同期 0 回 / 禁止コード E=0 0 個
* 指数ヒストグラム E0=0 E1=4942 E2=134 E3=312 E4=994 E5=404 E6=819 E7=4387
* 無効スロットの 1 の数 3024 / 0 の数 2972
* CH1 peak 32768 / rms 19737.2
* CH2 peak 32768 / rms 16910.8
```

1 行目（`* out.wav : ...`）は `-v` の有無によらず必ず出る。残りが `-v` で増える統計。

`.wav` / `.wav.zst` へ直接パイプすると生キャプチャが残らないため、**この統計が信号の
健全性を確認する唯一の手段になる**。[opm-writer.py](opm-writer.md) はパイプ経路で常に `-v` を付ける。

主に見るべき点:

| 項目 | 正常な状態 |
| --- | --- |
| φ1 の実測値 | 期待値 (φM/2) と一致する。1% 以上ずれると警告が出る。ずれていれば `--map` / `--phim` / `--la-rate` のどれかが間違っている |
| 再同期 | 0 に近い。多い場合は φ1 に対してサンプル数が足りていない（16MHz でのキャプチャを検討） |
| 禁止コード `E=0` | 0。ビット位相がずれていると増える |
| 無効スロットの 0/1 の数 | 両方それなりの数がある（3bit のダミーで、デコーダは無視する） |
| peak / rms | 無音でないことの確認 |

## 補足: YM3012 のシリアルフォーマット

データシート (LSI-2130123, 1992-04) より。**同じ線を OPM 側は SO、YM3012 側は SD と呼ぶ。**
以下は OPM 側の名前 (`SO`) で統一する。

- 1 変換 = φ1 の 16 クロック。CH1 → CH2 の順なので **1 サンプル = 32 クロック**。
  φ1 = φM/2 なので出力レートは φM/64 になる。
- 16 スロットの内訳は `無効 × 3, D0..D9, S0, S1, S2`。
- 仮数は **LSB first の 10bit オフセットバイナリ**（符号付きにすると `m - 512`）、
  指数は `E = S2*4 + S1*2 + S0`。
- 線形値は `pcm = (m - 512) << (E - 1)`。**`E = 0` は禁止コード**で 0 として扱う。
- SO は φ1 の立ち上がりで取り込まれるため、読むのは立ち上がり直前の L 区間。
- SH2 の立ち下がりが CH1 のデータ列の終端、SH1 の立ち下がりが CH2 の終端。
  これをフレームの同期点に使う。
