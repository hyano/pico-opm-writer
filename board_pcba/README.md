# board_pcba — RP2350 / PCM5102A 直載せ基板

JLCPCB の **Economic PCBA** で組み立てる pico-opm-writer の基板。Raspberry Pi Pico 2 と
GY-PCM5102 のモジュールを使わず、RP2350A・PCM5102A・周辺部品を直接実装する。
モジュール側に重複していた電源回路・USB・水晶を基板側へ統合してある。

**ファームウェアのピン割り当ては [README.md](../README.md) §1.1 の接続表と同一。**
`src/opm.h` の `OPM_PIN_*` / `src/ym3012.h` の `YM3012_PIN_*` / `src/button.h` の
`BUTTON_PIN_*` はそのまま使える。

回路図・部品配置・配線・GND ベタまで**一通り完成している**。ERC / DRC ともエラー 0 件（§8）。

## 2. 回路の構成

```
USB-C VBUS ─┬─ +5V ─┬─ U4 AMS1117-3.3 ── +3V3   RP2350A / フラッシュ / PCM5102A デジタル
            │       ├─ U5 XC6206P332  ── +3.3VA PCM5102A の AVDD / CPVDD
            │       └─ U6 YM2151 VDD
            └─ C1 10uF + C2 100nF

+3V3 ─ U1 VREG_VIN ─┐ RP2350 内蔵スイッチングレギュレータ
      ─ R9 33Ω ─ VREG_AVDD（C9 4.7uF）
                VREG_LX ─ L1 3.3uH ─ VREG_FB = +1V1 ─ DVDD ×3
```

回路図のブロック分け:

| ブロック | 内容 |
| --- | --- |
| A. USB-C ・ 電源 | J1、CC プルダウン、USB 直列終端、U4 / U5 の 2 系統 LDO |
| B. クロック ・ フラッシュ ・ 起動 | X1、U2、BOOTSEL (SW4)、RESET (SW3) |
| C. RP2350A | U1、デカップリング、内蔵レギュレータの外付け部品 |
| D. YM2151 (OPM) | U6、/CS プルアップ、デカップリング |
| E. PCM5102A ・ 音声出力 | U3、I2S 直列抵抗、チャージポンプ、出力フィルタ、J2 |
| F. ユーザー I/F ・ デバッグ端子 | SW1 / SW2、LED、SWD / UART / DAC プローブ、取付穴 |

ブロック間はネットラベルだけでつないである。ネット名は現行 [board/](../board/) を踏襲し、
I2S のみ PCM5102A のピン名に合わせて `LRCK` としている。

### 2.2 PCM5102A

GY-PCM5102 の既定ジャンパ設定をハードワイヤしてある。

| ピン | 接続 |
| --- | --- |
| 1 CPVDD / 8 AVDD | `+3.3VA`（U5 の出力。100nF を各ピンに 1 個ずつ） |
| 20 DVDD | `+3V3`（100nF） |
| 18 LDOO | 内蔵 1.8V LDO の出力。100nF + 10µF で `GND` へ |
| 2 CAPP / 4 CAPM | 2.2µF のフライングキャパシタ |
| 5 VNEG | 2.2µF で `GND` へ |
| 12 SCK | `GND`（内蔵 PLL モード） |
| 16 FMT | `GND`（I2S） |
| 11 FLT | `GND`（Normal latency） |
| 10 DEMP | `GND`（De-emphasis off） |
| 17 XSMT | `+3V3`（soft un-mute） |
| 13 BCK / 15 LRCK / 14 DIN | 22Ω 直列で GP26 / GP27 / GP28 |
| 6 OUTL / 7 OUTR | 470Ω → J2.T / J2.R、各々 2.2nF で `GND` へ |

**CPVDD はチャージポンプの電源で、TI のデータシートは AVDD と同じアナログ 3.3V に置く**
（§10.1.1 の Figure 33、§11.1 の Table 12）。デジタル側から取ると、チャージポンプの
パルス電流がアナログ電源へ回り込む。

**470Ω + 2.2nF は TI のデータシートが指定するポストフィルタ**（fc ≈ 154kHz）。
TI は THD+N・SNR・チャンネルセパレーションの規格値をすべて
「10kΩ 負荷 + 470Ω 出力抵抗 + 2.2nF シャント」の条件で規定しているので省略しない。
出力はチャージポンプで GND センターになるため DC カットのコンデンサは要らない。

### 2.3 YM2151 の /CS プルアップ

**R11: `~{CS}` → `+3V3` に 1kΩ。** 電源投入から `opm_init()` が /CS を H にするまでの間、
RP2350 のパッドは入力＋内部プルダウンなので、これが無いと OPM が D0-D7 を駆動する窓ができる
（[README.md](../README.md) §1.3）。

プルアップ先を 5V ではなく **3.3V** にした理由:

- **YM2151 の全入力の VIH は min 2.0V**（TTL しきい値。VIL は max 0.8V、入力リークは
  Vi=10V で 0.1µA 以下）。**RP2350 の内部プルダウンは IOVDD=3.3V で 36kΩ〜113kΩ。**
- この 2 つから、`opm_init()` 前の /CS 電位は次のようになる。

  | プルアップ | R_PD=36k | R_PD=113k | VIH 2.0V への余裕 | /CS Low 時の吸い込み | GP11 の最大電圧 |
  | --- | --- | --- | --- | --- | --- |
  | +5V / 10kΩ | 3.91V | 4.59V | +1.9V | 0.5mA | **4.59V** |
  | +3V3 / 10kΩ | 2.58V | 3.03V | +0.58V | 0.33mA | 3.3V |
  | **+3V3 / 1kΩ** | **3.21V** | **3.27V** | **+1.2V** | 3.3mA | 3.3V |

- 通常動作では GP11 が 3.3V で /CS を駆動するので、5V にしても H レベルは良くならない。
  1kΩ なら起動直後も**通常駆動時と同じ電位**になる。
- 5V プルアップは、VBUS が立って 3.3V がまだ立ち上がり切っていない間、IOVDD 不足のまま
  GP11 へ 5V を流し込む。3.3V なら GP11 は 3.3V レールに追従するだけで IOVDD を超えない。
- 1kΩ は他でも使っているので部品番号が増えない。3.3mA は RP2350 の 1 ピンあたりの駆動能力
  （12mA）にも合計値（`I_IOVSS_MAX` 100mA）にも収まり、/CS が L になるのは
  バスサイクル中だけなので平均消費は無視できる。

3.3V レールの立ち上がり中の短い窓は塞げないが、それは現行 [board/](../board/) と同じ状態で、
README §1.3 の整理がそのまま当てはまる。POR 解除から `opm_init()` までの長いほうの窓は塞げる。

## 4. 部品選定：検討した選択肢と選定理由

### 4.1 サイズと価格

| 項目 | 選択肢 | 採用 | 理由 |
| --- | --- | --- | --- |
| チップ抵抗 | 0402 / 0603 | **0402 に統一** | Economic PCBA の最小サイズが 0402 |
| µF 級コンデンサ | 全部 0402 / 全部 0603 / 電圧で使い分け | **電圧で使い分け** | 0402 の Basic 品は 6.3V しかなく DC バイアスで大きく容量が減る。`+5V` と `+3V3` の 10µF は 0805/25V、`+3.3VA` と LDOO の 10µF は 0603/10V |
| VREG 周辺の 4.7µF | 0402 / 0603 | **0402** | RPi の設計ガイド §2.1 が 0402 (1005 metric) を指定。レギュレータのレイアウトが critical なのでサイズを勝手に大きくしない |
| タクトスイッチ | 5.1×5.1mm / 3.9×3×2mm | **C720477 (3.9×3×2mm)** | Basic かつ在庫 90 万個。KiCad 標準 `SW_SPST_TS-1088-xR020` がこの部品のデータシートから起こされている |

### 4.2 フラッシュ容量

| 選択肢 | 判断 |
| --- | --- |
| 2MB (W25Q16) | 曲データが約 1.7MB までで足りない |
| 4MB (W25Q32) | Pico 2 と同容量でファームウェアの変更が不要だが、**Extended 品しかなく 16MB の Basic 品より高い** |
| **16MB (W25Q128JVSIQ / C97521)** | **採用。** Basic で在庫 10 万個。RP2350 がサポートする最大容量で、RPi のリファレンス設計と同一部品。FatFs 領域が約 15.7MB になる（ファームウェア側の対応は §7） |

### 4.3 USB D+/D− の直列 27Ω

RPi の設計ガイド §5.1 が「USB のインピーダンス規格を満たすために 27Ω の直列終端が必要」と
明記している。**JLCPCB に Basic の 27Ω は 0402 / 0603 / 0805 のいずれにも無く**、手数料が
同じくかからない Preferred ティアにも無い。Basic の 0402 抵抗で選べる値は
0 / 10 / 22 / 33 / 49.9 / 100 / 120 / 200 / 220 / 330 / 470 / 510 / 1000 Ω の 13 種だけ。

| 個数 / 1 本あたり | 最良の組み合わせ | 実効値 |
| --- | --- | --- |
| 2 個 | 33 ∥ 200 | 28.32Ω (+4.9%) |
| 2 個 | 33 ∥ 120 | 25.88Ω (−4.1%) |
| 3 個 | 22 + (10 ∥ 10) | 27.00Ω（厳密） |
| 3 個 | 33 ∥ (49.9 + 100) | 27.05Ω (+0.2%) |

2 個では ±4% 以上ずれ、±1% に入れるには 1 本あたり 3 個（D+/D− で計 6 個）要る。
Extended 手数料は枚数に依存しない $3 なので 10 枚なら 1 枚あたり $0.30 にしかならず、
**USB はこの基板の唯一のホストインタフェースなので終端を分割してまで節約しない**。
33Ω 単体（R9 と共通化して新規部品ゼロ）も検討したが、+22% となり USB 2.0 フルスピードの
ドライバ出力インピーダンス規格（28〜44Ω、直列抵抗込み）を超える可能性がある。

### 4.4 RPi の設計ガイドに従った部分

RP2350 の内蔵スイッチングレギュレータ周辺は、RPi の設計ガイドが
「部品選定ごと真似しろ、外れるなら自己責任」と明記しているので全面的に合わせてある。

| 部品 | 選択肢 | 採用と理由 |
| --- | --- | --- |
| 12MHz 水晶 | Basic の 20pF 品 (C9002) / Extended の 12pF (C70565) / **ABM8-272-T3 (C20625731)** | **ABM8-272-T3。** ガイド §4 が名指しで推奨し、直列 1kΩ は「最大 ESR 50Ω・IOVDD 3.3V」に合わせて水晶を過大駆動しないよう選んだ値だと述べている。回路から外れると全温度域での検証が必要になる。負荷容量 15pF ×2 の直列 7.5pF に寄生 3pF を足して 10.5pF ≒ CL 10pF |
| VREG インダクタ | Sunlord SWPA3015 (C48020, 3×3mm) / **AOTA-B201610S3R3-101-T (C42411119)** | **AOTA。** ガイド §2.1 が「巻き方向が逆だと漏れ磁束が出力コンデンサ C7 に干渉し、RP2350 内部の制御回路を乱す」ため極性ドット付き・リール内で向きが揃った専用品を Abracon に作らせたと述べ、代替は自己責任としている |
| QSPI_SS の 10kΩ | 実装 / **DNF** | **DNF。** ガイド §3.1「この特定のフラッシュ (W25Q128JVS) では外付けプルアップは不要と判明した。別のフラッシュを使うときのために footprint だけ用意してある」 |
| アナログ LDO | ME6211C33M5G (C82942) / SPX3819 (C9055) / **XC6206P332MR-G (C5446)** | **XC6206。** ME6211 は在庫 9 個で実質発注不可。XC6206 は Basic・在庫 45 万個で、200mA / ドロップ 250mV@100mA は AVDD の約 25mA に十分 |
| PCM5102A の電源 | LDO 1 個で共通 / フェライトビーズで分離 / **LDO 2 個** | **LDO 2 個。** RP2350 内蔵バックのスイッチングノイズをアナログ側から切り離す。追加は LDO 1 個とコンデンサ 2 個だけ。AVDD と CPVDD は TI のデータシートどおり同じ `+3.3VA` に載せ、DVDD だけ `+3V3` から取る |
| 10µF の置き場所 | 電源ピンごと / **レギュレータの入出力だけ** | **レギュレータの入出力だけ。** `+5V` は C1（U4 / U5 の入力）、`+3V3` は C3（U4 の出力）、`+3.3VA` は C6（U5 の出力）の 1 個ずつで、デカップリングバンクには置かない。RPI-RP2350A-MINIMAL と同じ配置で、AMS1117 / XC6206 が安定条件として要求する出力コンデンサもこれで満たす。各 IC のピン直近は 100nF が受け持つ |

| AOTA-B201610S3R3-101-T | `pico-opm-writer:abracon_aota-b201610s3r3-101-t` | KiCad 標準の 2016 メトリック品はどれもパッドが違う（最も近い `L_Changjiang_FTC201610S` で ±0.65mm / 0.8×1.7mm、実物は ±0.7mm / 0.7×1.7mm）ため §6 のとおり複製した |

USB-C はレイアウト着手時に 1:1 印刷で最終確認する。合わなければ
`easyeda2kicad --lcsc_id C2765186 --footprint` で取り込む。

### 4.6 C8 / C10 のパッド間を広げた 0402

**`VREG_LX`（U1 pin 48 → L1）は C8 と C10 のパッドの間を通す。** RPi のリファレンス設計は
この 2 個（向こうの C6 / C7）だけ専用の land pattern を使っており、KiCad 標準の 0402 では
配線が通らない。

| フットプリント | パッド | パッド内側の隙間 | 0.15mm 配線（両側 0.15mm クリアランス）|
| --- | --- | --- | --- |
| RPi `generic_capc1005x50_wide` | 0.47 × 0.55 @ ±0.515 | **0.56mm** | 通る |
| RPi `generic_capc1005x50`（通常） | 0.55 × 0.55 @ ±0.475 | 0.40mm | 通らない |
| KiCad 標準 `C_0402_1005Metric` | 0.56 × 0.62 @ ±0.48 | 0.40mm | **通らない** |

そのため `rpi_capc1005x50_wide.kicad_mod` を複製して C8 / C10 に割り当てている（出典は §6）。
コートヤードだけは RPi の 0.94mm ピッチ配置に収まるよう 1.8 × 0.9mm に広げてある。
**C8 / C10 を標準の 0402 に戻すと `VREG_LX` が通らなくなる。**

部品自体は同じ 0402 のチップコンデンサなので、BOM も JLCPCB の部品番号も変わらない。

### 5.1 仕様

| 項目 | 値 |
| --- | --- |
| 外形 | **46 × 47.5mm**、角 R2mm |
| 層数 / 板厚 | **2 層 / 1.6mm** |
| 配線 | 753 本 / 総延長 1579mm（F.Cu 551 本 / B.Cu 202 本） |
| ビア | **167 本すべて φ0.45mm / ドリル 0.2mm**（アニュラーリング 0.125mm） |
| GND | 基板全面のベタゾーン 1 個（F.Cu + B.Cu）＋ **スティッチングビア 84 本**（§5.7） |
| 実装面 | **表面のみ**（Economic PCBA は片面実装） |
| 手はんだ | `U6` / `J2` / `J3` の 3 点だけ（§3.1） |

ネットクラスと実際に使われている配線幅:

| ネットクラス | 幅 | クリアランス | 本数 |
| --- | --- | --- | ---: |
| Default | 0.15mm | 0.15mm | 498 |
| Power / USB / VREG | 0.2mm | 0.15mm | 217 |
| Analog | 0.3mm | 0.15mm | 16 |
| （局所ネックダウン） | 0.125〜0.142mm | 0.15mm | 22 |

**ネックダウンの 22 本は QFN-60（0.4mm ピッチ）の脱出部などで 0.15mm が物理的に入らない
箇所。** JLCPCB の 1oz 標準能力は 0.10mm 幅 / 0.10mm 間隔なので製造上の問題はない。
DRC の `min_track_width` はこれに合わせて 0.12mm にしてある。

DRC ルール: `min_clearance` 0.15 / `min_via_diameter` 0.45 /
`min_through_hole_diameter` 0.2 / `min_via_annular_width` 0.125 /
`min_hole_clearance` 0.2 / `min_copper_edge_clearance` 0.3。

**部品は 0.5mm グリッドに載せてある。** 例外は次の 2 つだけ。

- **RPi のリファレンス設計から 1:1 で複製した部品**は U1 相対座標がグリッドに乗らない。
  対象は `RPI-RP2350A-MINIMAL_R4-S1.kicad_pcb` の以下の部品で、
  U1 の回転（270°）に合わせてクラスタごと回してある。

  | ours | RPi | 役割 |
  | --- | --- | --- |
  | `C8` `C10` `L1` `C9` `R9` | C6 / C7 / L1 / C9 / R3 | 内蔵レギュレータ。§4.4 のとおりここから外れると自己責任 |
  | `R5` `R6` | R7 / R8 | USB の 27Ω 直列終端 |
  | `C21` | C12 | 53 / 54 ピンで共用する 100nF |

  `L1` の極性ドットの向きも RPi と一致させてある。
- **`J1` (USB-C)** は挿入口が基板端に載る Y 座標に置いてある。

**リファレンスのシルクはすべて水平**（`KeepUpright` 有効）。0.25mm グリッドに載せ、
部品の中心に揃えてある。68 個中 31 個は自分の部品から 0.5mm 以内、最も遠いもので 2.3mm。
密集部（U1 のデカップリング列と PCM5102A のアナログ部）は 0.8mm の文字が
入る隙間が無いため、これ以上は詰められない。

### 5.2 ビア寸法の根拠

JLCPCB の仕様は資料によって食い違っている（同社の Q&A ページ自身が矛盾を認めて
サポート問い合わせを案内している）。確認できた範囲では次のとおり。

| 出典 | 記載 |
| --- | --- |
| 能力表（2 層） | 最小ビア穴 0.15mm・最小ビア径 0.25mm。ただし **0.15mm 穴は割増** |
| 能力表の推奨値 | ビア穴 **0.2mm** / ビア径 **0.35mm** |
| ブログ | 推奨アニュラーリング **0.13mm**、「ドリル **0.3mm 以上が標準プロセス**」 |

採用した φ0.45 / 0.2mm は、

- ドリル 0.2mm は能力表の**推奨最小値**。0.3mm 未満なので小径穴として基板製造費に
  割増が付く可能性はあるが、**Economic PCBA（実装）の可否には影響しない**
- アニュラーリング 0.125mm は推奨 0.13mm にほぼ一致し、JLCPCB 自身の推奨ビア
  （0.35/0.2 → 0.075mm）よりはるかに健全

**ビア径を後から広げることはできない。** 配線済みの基板で実測したところ、
φ0.45 → φ0.5 で 234 件、φ0.6 で 134〜141 件のクリアランス違反が出る。
寸法を変えるならネットクラスを直してから配線をやり直すこと。

### 5.3 ブロック配置

コネクタは 2 つとも**下辺**に出す。

```
      0      10      20      30      40  46
  0 +---------------------------------------+
    | +-----------------------------+ SW1SW2|
    | |   U6  DIP-24 socket (横置き) | SW3SW4|
    | |   内側: C25                 | D1 R10|
 20 | +-----------------------------+    H2 |
    | C15 C11 C14  R11 R2 R1  U2 flash      |
    | X1  C22             C21 R5 R6  R12-14 |
 30 | C16 U1 RP2350A  C8 C10 L1   U3 PCM5102|
    | C12 R3 C17   C9 R9   C26-C28  U5 C5-C7|
    | J3  C18-C20         C30-C32 R15 R16   |
 40 | H1  C1-C3  R7 R8    C33 C34           |
    |    [J1 USB-C]   U4     [J2 jack] ===> |
 47.5+---------------------------------------+
```

**U1 は 270° 回してある。** GPIO2–11（`D0`–`D7` / `A0` / `~{CS}`）の並ぶ辺が
真上の U6 を向き、残りの辺は次のようになる。

| U1 の辺 | 向き | 主な信号 | 向かい合う部品 |
| --- | --- | --- | --- |
| GPIO0–11 (1–15) | 上 | `D0`–`D7` `A0` `~{CS}`（GP0/GP1 は未使用） | U6 の下段 |
| GPIO12–18 ほか (16–30) | 左 | `~{WR}` `~{RD}` `~{IC}` `ΦM` / `XIN` `XOUT` / SWD / `RUN` / `~{IRQ}` `SO` `Φ1` | X1、J3、U6 の上段左端 |
| GPIO19–28 ほか (31–45) | 下 | `SH1` `SH2` / ボタン / `LED` / I2S | C18–C20、U3 |
| VREG・USB・QSPI (46–60) | 右 | VREG 一式 / `USB_DP` `USB_DM` / QSPI | L1、R5/R6、U2 |

**U6 は 90° 回してある。** 下段（U1 側）が 1–12 ピン、上段が 24–13 ピン。

| 段 | 左→右 |
| --- | --- |
| 上段 | `ΦM` `Φ1` `VDD` `SO` `SH1` `SH2` `D7` `D6` `D5` `D4` `D3` `D2` |
| 下段 | `GND` `~{IRQ}` `~{IC}` `A0` `~{WR}` `~{RD}` `~{CS}` CT1 CT2 `D0` `GND` `D1` |

この向きにすると **`D2`–`D7` が U1 の並び順のまま**上段へ抜け、`ΦM` / `Φ1` /
`SO` / `SH1` / `SH2` が U1 の左辺の至近（上段の左端）に来る。
**`SH1` / `SH2` だけは U1 の下辺から出るので回り込みになる**が、
これは 62.5kHz のサンプルホールドストローブなので長さを許容している。

**U3 は 90° 回してある。** I2S（`BCK` / `LRCK` / `DIN`）が上、`OUTL` / `OUTR` が下。
データシート §12.1 の「I2S のクロック・データを OUTL / OUTR から離す」を
パッケージの反対側に分けることで満たし、アナログ出力は真下の J2 へ最短で降りる。

### 5.4 ソケットの内側に置いた部品

DIP-24 ソケットは 2 列の間が 15.24mm 開いている。ここに `C25`（U6 の VDD の 100nF）を
置いて面積を稼いでいる。**U6 のコートヤードの中にあるので DRC が衝突と判定する。**
`pico-opm-writer_pcba.kicad_dru` の `socket_inner_parts` ルールで例外にしてある。

反対の列へ渡る信号もソケットの内側を通している。
**表層を通せば裏面のベタ GND を切らずに済む。**

### 5.5 配線するときの注意

RP2350 の設計ガイドから。回路図には現れないのでここに残す。

- **USB は 90Ω 差動が理想だが、2 層 1.6mm では現実的な線幅で作れない。**
  RP2350 の USB はフルスピード (12Mbps) なので、
  「対を短く・密結合・等長・**直下は切れ目のない裏面 GND**」で通す（設計ガイド §5.1）。
  J1 は U1 の右辺（`USB_DP` / `USB_DM`）の真下に置いてある
- **R5 / R6（27Ω）は RP2350 の至近**、フラッシュ周りの R1 / R2 はフラッシュの至近（設計ガイド §3.1・§5.1）
- **`VREG_PGND` の大電流リターンは、他の GND を乱さずに PGND ピンへ直接戻す**（§2.1）
- **L1 は極性ドットの向きを RPi のレイアウトに合わせる**（設計ガイド §2.1。座標は本書 §5.1）
- **水晶の配線は極力短く。** 寄生容量を 3pF と見込んで負荷容量を決めている（§4）
- 電源ピンごとに 100nF を至近に置く。53 / 54 ピンだけ `C21` 1 個を共用している（§2.2.1）
- SMD 部品はすべて表面に置く（Economic PCBA は片面実装）
- **`VREG_LX` は C8 / C10 のパッドの間を通す**（§4.6）

PCM5102A のデータシート §12.1 から。

- **電源とチャージポンプのデカップリング（C26 / C27 / C28 / C29 / C30 / C31 / C32）は
  U3 の直近に置く**
- **I2S のクロック・データ配線を OUTL / OUTR から離す**（§5.3 で U3 の向きにより分離済み）
- `AGND` / `DGND` / `CPGND` は分離せず共通グラウンドでよい。表層を信号、裏層を GND ベタにする

`+5V` のバルクは U4 / U5 の入力側の C1 だけで、U6 の VDD には C25 (100nF) しか付いていない
（§4.4）。**J1 から U4 / U5 を経て U6 までの `+5V` を短く太く引く。**

### 5.6 freerouting を使うときの手順

配線は KiCad の Specctra DSN / SES 経由で freerouting に投げている。
**DSN のエクスポートは GUI 専用**（`kicad-cli` には無い）。

1. KiCad で基板を開き、**Board Setup → Net Classes のビア寸法が φ0.45 / 0.2mm に
   なっているか先に確認する**
2. File → Export → Specctra DSN
3. freerouting で自動配線 → Export Specctra Session (.ses)。
   **両層とも preferred direction は無効にする**（有効だとマンハッタン配線になり
   ビアが激増して裏面 GND が細切れになる）
4. File → Import → Specctra Session

**KiCad を開いたままプロジェクトファイルを外部から編集しないこと。** KiCad は
プロジェクト設定をメモリに持っていて保存時に書き戻すため、`.kicad_pro` の
ネットクラスや DRC ルールの編集が失われ、古い設定のまま DSN が出力される。

取り込み後にやること:

- **SES 由来の小さな銅箔ゾーンを削除する。** freerouting は一部の接続をポリゴンで
  出力し、KiCad はそれを 1mm² 未満の小さなゾーンとして取り込む（今回は 312 個）。
  削除しても未接続は増えない
- **0.12mm 未満の配線が無いか確認する。** freerouting は DSN が 0.15mm を宣言していても
  0.1124mm の配線を出すことがある（今回は 21 本）
- ゾーンを再フィルして DRC を通す

### 5.7 GND のベタとスティッチングビア

GND は **F.Cu と B.Cu をまたぐ 1 個のゾーン**で、基板端から 0.3mm 内側まで塗ってある。

- **スティッチングビア 84 本**を 5mm 格子で入れて表裏のベタをつないでいる。
  格子点に置けない場合は周囲 ±1mm を 0.25mm 刻みで探し、それでも無理なら飛ばす
- ビアは他の銅箔から 0.15mm、**穴からは 0.2mm（KiCad は「穴の縁 ↔ 相手の銅箔」で測る）**、
  基板端からは 0.3mm + ビア半径を確保している
- ゾーンは **島の除去を「常に」** に設定してある。どこにもつながらないベタは残らない
- 最小幅 0.25mm。これ以下の細いヒゲは塗られない

結果として、F.Cu は 7 領域（最大 1394mm²）、B.Cu は 3 領域（最大 1486mm²）で、
**すべての領域が 4 点以上でつながっている**（1 点だけで釣り下がったアンテナ状のベタは無い）。

### 5.8 ケース（3D プリント）

- 取付穴は **M2 × 2 箇所**（左下 H1 / 右上 H2）。ソケットへ YM2151 を押し込む力を受けるので、
  **ケース側にソケット真下を支えるボスを立てる**こと
- 操作部は右辺に固めてある（SW1 / SW2 / SW3 / SW4 / D1）。天面に穴を開ける
- コネクタは下辺に 2 つ。J2 のバレルは基板端から突き出す

## 7. ファームウェア側の未対応事項

16MB フラッシュを選んだので、この基板でファームウェアを動かすには次が要る。

- `PICO_FLASH_SIZE_BYTES` を 16MiB にする独自ボードヘッダ（`pico2.h` を include して上書き）
- `cmake ... -DFLASH_TOTAL_BYTES=16777216`

`src/flash_disk.c` の `_Static_assert` が両者の一致を検査するので、片方だけ変えると
コンパイルが落ちる。
