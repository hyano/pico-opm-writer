# YM2151 の DAC 2 スロット (CH1 / CH2) の関係

`tools/opm-writer.py`（[docs](../../docs/opm-writer.md)）が出す WAV は、YM3012 のシリアル
ストリームの 2 スロット CH1 / CH2 をそれぞれ L / R に割り当てたもの。**1 チャネルだけを
`RL=both` で鳴らせば L と R はサンプル単位で一致するはず**だが、実際には一致しない。
これがデコードの誤りなのか実機がそう出しているのかを切り分け、後者ならその仕組みを突き止める。

このドキュメントでは、**実測**（`wav/` の 16 条件で確かめたこと）、**推測**（実測から導いた
説明。「〜と考えられる」と書く）、**未確認**（このデータでは決まらないこと）を書き分ける。
実測値は `./lr_relation.py wav/*.wav.zst` でいつでも再現できる。

## 1. 解析結果の要約

| 項目 | 結論 | 根拠 |
| --- | --- | --- |
| R に出る値 | オペレータのレジスタオフセットで 2 群に分かれ、`R[i] = L[i]`（`+0x00`,`+0x08`）/ `R[i] = L[i+1]`（`+0x10`,`+0x18`） | [§3.2](#32-r-は-l-の-1-サンプル後の値と混ざる)（16 条件、`eq` = 1.0000） |
| 4 オペレータを同条件で鳴らしたとき | `R = (L[i] + L[i+1]) / 2`（L の 2 タップ移動平均） | [§3.3](#33-両群が均等なら-r-は-l-の-2-タップ移動平均)（`slow_4op_both` で `davg` −60.8dB、振幅比が `cos(π f / fs)` と一致） |
| `+0x08` のオペレータ | 出力が他の 3 個より 1 サンプル遅れる | [§5.2](#52-オペレータ間の時間差)（位相差 0.9405rad = 1.000 サンプル） |

## 2. 判明した仕様

### 2.1 R に出る値はオペレータのレジスタオフセットで決まる

オペレータは 2 群に分かれ、群ごとに R の出方が変わる。

| 群 | オペレータ（ベースからのオフセット） | R に出る値 |
| --- | --- | --- |
| A | `+0x00`, `+0x08` | `R[i] = L[i]` |
| B | `+0x10`, `+0x18` | `R[i] = L[i+1]` |

両群が同じ量だけ鳴っているとき、和はちょうど中点になる。

    R[i] = (L[i] + L[i+1]) / 2

これは L に `H(f) = cos(π f / fs)` のローパスを掛けたもの（2 タップ移動平均）で、
**R は L と独立なサンプルではない**。

### 2.2 解析での使い分け

**波形解析には L (CH1) だけを使う。** [../lfo_noise/](../lfo_noise/) の調査は L だけを
見ているので、この件の影響を受けていない。

ステレオ定位を本当に確かめたいとき（`RL` の効きを見るなど）は L / R の両方に意味が
あるが、その場合も片方だけで判断せず [§5.1](#51-全-16-条件) のような条件分けでキャプチャすること。

## 3. 結論の根拠

[§3.1](#31-デコードは正しい) は前提の確認で、L と R の食い違いがデコーダ由来でないことを示す。
これが済んでいるので、[§3.2](#32-r-は-l-の-1-サンプル後の値と混ざる) 以降を OPM の出力そのものの
話として読める。[§1](#1-解析結果の要約) の各行に対応するのは [§3.2](#32-r-は-l-の-1-サンプル後の値と混ざる) と
[§3.3](#33-両群が均等なら-r-は-l-の-2-タップ移動平均)。

### 3.1 デコードは正しい

- `fast_4op_left`（`RL` = L のみ）では **R が全サンプル厳密に 0**、
  `fast_4op_right` では **L が全サンプル厳密に 0**。CH1/CH2 と L/R の対応、
  SH2 立ち下がりを同期点に取る取り方、13bit ワードの切り出し位置がすべて正しいことの
  独立な裏づけになる。
- 単独オペレータの条件では L と R が**整数値で完全一致**する（`eq0` = 1.0000、残差ゼロ）。
  ビット位相がずれていれば厳密一致は起こらない。
- `tools/opm-dac2wav.py` の統計でも禁止コード `E=0` は 0 個、再同期も 0 回。

### 3.2 R は L の 1 サンプル後の値と混ざる

[§5.1](#51-全-16-条件) の 16 条件から:

- **同じ群だけを鳴らすと L と R は厳密に一致する**か、厳密に 1 サンプルずれる
  （`fast_op00_op08` → `b=a`、`slow_op10_op18` → `b=a[+1]`。どちらも `eq` = 1.0000）。
- **両群から 1 個ずつ鳴らすと `R = (L[i] + L[i+1]) / 2`** になる
  （`fast_op00_op10` / `fast_op00_op18` / `slow_op00_op10` すべて `davg` ≈ −61dB）。
- 4 オペレータすべてを同条件で鳴らすと 2 個ずつに割れるので、やはり
  `R = (L[i] + L[i+1]) / 2`（`slow_4op_both` で −60.8dB）。
  **これが [../lfo_noise/](../lfo_noise/) のキャプチャで L/R が一致しない理由**。

結論が搬送波に依存しないことは、`fast`（9353.6Hz）と `slow`（492.0Hz）の両方で
同じ群分けが出ることから確かめられる（[§4.2](#42-2-種類の搬送波)）。

### 3.3 両群が均等なら R は L の 2 タップ移動平均

`fast_op00_op10` では `rms_b / rms_a` = 10299.8 / 11553.7 = 0.8915 で、9353.6Hz における
理論値 `cos(π × 9353.6 / 62500)` = 0.8915 と一致する。残差 `davg` が −61dB まで落ちることと
合わせて、平均の関係が近似ではなく厳密であることを示している。

## 4. 解析方法

### 4.1 測定系

- ターゲット: Raspberry Pi Pico 2 + YM2151、φM = 4.000000MHz（`OPM_CLOCK_MODE_4MHZ`）
- OPM の内部サンプルレート fs = φM / 64 = **62500Hz**
- ロジアナ: fx2lafw、8MHz サンプリング。CH0=φ1 / CH1=SO / CH2=SH1 / CH3=SH2
- WAV: 62500Hz / 16bit / stereo（当時の `tools/opm-dac2wav.py` が生成）

`opm_lr_seq.txt` は [../lfo_noise/opm_seq.txt](../lfo_noise/opm_seq.txt) から **LFO 関連の
書き込みを全部落とした**もの。`NFRQ` / `LFRQ` / `PMD` / `AMD` / `W` / `PMS` / `AMS` は
書かず、リセット直後の 0 のまま使う。したがって出力は**変調のかかっていない持続音**。

- `ALG=7`（4 オペレータすべてキャリア）/ `FL=0` / 4 オペレータとも同じ `MUL`
- 各オペレータ: `AR=31` / `D1R=0` / `D2R=0` / `D1L=0` / `RR=15`、AMS-EN は off
- プレースホルダは `@KC@` `@MUL@` `@RL@` `@TL0@` `@TL1@` `@TL2@` `@TL3@` `@TIME@`

**オペレータはレジスタオフセットで呼ぶ。** ch0 の 4 スロットは DT1/MUL が
`0x40` / `0x48` / `0x50` / `0x58`、TL が `0x60` / `0x68` / `0x70` / `0x78` で、
ベースからのオフセット `+0x00` / `+0x08` / `+0x10` / `+0x18` が識別子になる。
`@TL0@`〜`@TL3@` はこの順に対応する（`TL=0x00` で最大音量、`0x7F` で実質無音）。

### 4.2 2 種類の搬送波

| 名前 | KC / MUL | 周波数（実測） | 周期（実測） | 用途 |
| --- | --- | --- | --- | --- |
| `fast` | `5e` / `08` | 9353.6Hz | 6.682 サンプル | 1 サンプルの時間差が大きな位相差になる。単独オペレータの判別向き |
| `slow` | `4a` / `01` | 492.0Hz | 127.03 サンプル | オペレータ間の時間差が無視できる。「隣接 2 サンプルの平均」の確認向き |

周波数と周期は実機のキャプチャから測った値（等分平均律で計算した値は 9355.4Hz / 6.680
サンプルと 491.7Hz / 127.11 サンプル）。以下の数値はすべて実測値の方で計算している。

両方でキャプチャするのは、結論が搬送波に依存しないことを示すため。

### 4.3 判定器 `lr_relation.py`

`a`（既定 L = CH1）を基準に `b`（既定 R = CH2）を見て、4 つの仮説の残差を並べる。

| 仮説 | verdict |
| --- | --- |
| `b[i] = a[i]` | `b=a` |
| `b[i] = a[i+1]` | `b=a[+1]` |
| `b[i] = (a[i] + a[i+1]) / 2` | `b=avg` |
| 片側が無音 | `b=0` / `a=0` / `silent` |
| どれでもない | `不明` |

出力は 1 ファイル 1 行の TSV。主な列:

| 列 | 意味 |
| --- | --- |
| `nz_a` / `nz_b` | 非ゼロのサンプル数。RL を片側だけにしたとき反対側が厳密に 0 か |
| `eq0` / `eq1` | `b[i] == a[i]` / `b[i] == a[i+1]` が**厳密に**成り立つ割合 |
| `d0_db` / `d1_db` / `davg_db` | 3 仮説の残差 rms（`rms_a` に対する dB）。`-999.0` は残差ゼロ |
| `frac_delay` | `b = (1−f)a[i] + f·a[i+1]` を最小二乗で解いた `f` |
| `jumps` / `jd*_db` | `|Δa|` が大きい点だけに絞った同じ残差 |

判定の順番と閾値:

1. 片側または両側が完全に無音なら `b=0` / `a=0` / `silent`
2. `eq0` か `eq1` が **0.999 以上**なら、その厳密一致で決める（最も強い証拠）
3. 段差の点が **32 点以上**あればそこだけの残差で、無ければ全区間の残差で比べる
4. 最良の残差が **−34dB** より大きい、または 2 位との差が **6dB** 未満なら `不明`

段差のある波形（AM を掛けたキャプチャ）では `jd*` が決め手になる。**半サンプルの遅延なら
段差の前後どちらかの値になり、平均なら中点に落ちる**ので、滑らかな区間だけを見ても
両者は区別できない。本ディレクトリのキャプチャは LFO を切ってあり段差が無いので、
代わりに整数値の厳密一致 (`eq0` / `eq1`) が決め手になる。

`不明` は正常な測定結果の 1 つなので終了コードは 0（`fast_4op_both` が実際にそうなる）。
1 を返すのは入力が読めなかったときと `--self-test` が落ちたときだけ。

`--self-test` は合成波形 16 ケース（3 種類の搬送波周期 × 5 仮説 + 両側無音）で判定が
期待どおりに出るかを見る。YM3012 の 10bit 仮数 + 3bit 指数への丸めも模しているので、
実データと同じ量子化ノイズの下で判別できることまで確認できる。

### 4.4 再現手順


### 5.2 オペレータ間の時間差

同じ搬送波で 2 オペレータを同時に鳴らし、和の rms を単独 rms の和と比べる。
位相が揃っていれば 1.0000 になり、ずれていればそのぶんだけ小さくなる
（`ratio = cos(Δφ/2)`）。搬送波が `fast`（T = 6.682 サンプル）だと 1 サンプルの
ずれが 0.94rad になるので敏感に出る。単独 rms は 4 オペレータとも 5776.8〜5776.9。

| 組 | 和の rms | / 単独の和 | 位相差 | 時間差 |
| --- | --- | --- | --- | --- |
| `+0x00` & `+0x08` | 10299.6 | 0.89145 | 0.9405 rad | **1.000 サンプル** |
| `+0x00` & `+0x10` | 11553.7 | 1.00001 | 0 rad | 0.000 サンプル |
| `+0x00` & `+0x18` | 11553.3 | 0.99997 | 0.017 rad | 0.018 サンプル |
| 4 オペレータすべて | 21254.8 | 0.91983 | — | — |

4 オペレータの 0.91983 は「3 個が同相、1 個 (`+0x08`) だけ 1 サンプルずれ」から計算した
`|3 + e^{i·0.9405}| / 4 = 0.91979` と一致する。`slow` 側でも
`+0x00` & `+0x08` の比は 0.99965（= 1.08 サンプルぶん、この搬送波での分解能の範囲で同じ）で、
残りの組は 1.0000 と揃う。

**この時間差は L/R の話とは別の軸**で、`+0x08` のオペレータだけが出力に届くまでに
1 サンプルよけいに掛かることを意味する。DAC の 2 スロットの分かれ方（[§2.1](#21-r-に出る値はオペレータのレジスタオフセットで決まる)）とは
グループの切れ方が違う（あちらは `+0x00`,`+0x08` / `+0x10`,`+0x18` で割れる）。

## 6. 考察

### 6.1 なぜ半フレーム遅れるのか

[§2.1](#21-r-に出る値はオペレータのレジスタオフセットで決まる) の 2 群を説明する仕組み（実測とデータシートのフレーム構造から導いたもので、
チップ内部を直接観測したわけではない）: 1 サンプル = φ1 32 クロックで、DAC は 16 クロック
ごとに CH1 → CH2 と送出する。**CH2 のラッチが CH1 の半フレーム後**にあり、その間に更新された
オペレータ（B 群）の寄与だけが次のサンプルの値に入れ替わっている、と考えられる。
A 群の寄与が `i`、B 群が `i+1` なので、両群の和が等しいときちょうど平均になる。

### 6.2 2 タップ移動平均が波形解析に及ぼす影響

両群が均等に鳴っている限り R は L のローパス（`H(f) = cos(π f / fs)`）で、fs/2 に近づく
ほど振幅が落ち、位相も半サンプルぶん遅れる。L と R を平均したり、どちらを見るかを
条件ごとに変えたりすると、この特性がそのまま解析結果に混ざる。
片側（L）に固定すれば素の出力をそのまま扱えるので、[§2.2](#22-解析での使い分け) の方針になる。

### 6.3 `fast_4op_both` だけ `不明` になる理由

[§5.2](#52-オペレータ間の時間差) の時間差による。`+0x08` が 1 サンプルずれているため A 群と B 群の和が
等しくならず、平均の関係が崩れる。搬送波が `slow` なら 1 サンプルのずれは無視できるので
`b=avg` に戻る（`slow_4op_both`）。判定器が壊れているのではなく、
平均の前提（両群が均等）が成り立っていないことを `不明` として正しく報告している。

## 7. 不明点・未解決事項

- **オペレータが `+0x00`,`+0x08` / `+0x10`,`+0x18` の 2 群に分かれる理由は未確認。**
  レジスタオフセットの上位ビットで割れているところまでは実測で分かっているが、
  それがスロットの処理順によるものか、DAC への送出順によるものかは決まらない。
- **`+0x08` のオペレータだけ 1 サンプル遅れる理由は未確認。** 現象は `fast` / `slow` の
  両方で再現するが（[§5.2](#52-オペレータ間の時間差)）、なぜ 4 スロットのうち 1 つだけなのかは分からない。
- **ALG=7 以外はキャプチャしていない。** 上の 2 点はどちらも、群分けや遅れが
  「スロット番号で決まる」のか「その結線でキャリアになっているスロットで決まる」のかを
  分けられていない。
- **`RL` を片側にした条件は `fast_4op_*` の 2 本しか無い。** オペレータごとに `RL` を
  変えたときの挙動は測っていない。

## 8. 今後の課題

- **群分けが ALG に依存するか**: `opm_lr_seq.txt` の ALG と各オペレータの `TL` を振り、
  モジュレータを含む結線で `+0x00`〜`+0x18` を単独に鳴らして `lr_relation.py` に掛ける。
  群分けがスロット番号のまま動かなければ「スロット番号で決まる」、結線に従って動けば
  「キャリアかどうかで決まる」と分けられる。
- **`+0x08` の 1 サンプル遅れ**: 同じ手順で ALG を変えたときに遅れるオペレータが移動するかを
  見る。`fast`（T = 6.682 サンプル）なら 1 サンプルが 0.94rad になるので、
  [§5.2](#52-オペレータ間の時間差) と同じ rms 比の測り方でそのまま判別できる。
- **`RL` と群の関係**: オペレータごとに `RL` を L のみ / R のみ / both に振り、
  片側だけを鳴らしたときの CH1 / CH2 の出方を見る。`RL` がスロット単位のミュートなら
  群分けはそのまま残るはずで、残らなければ `RL` が DAC のスロット割り当てに
  関与していることになる。
